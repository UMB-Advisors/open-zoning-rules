# Z0.14 Grok reviewer saw only the start and end of long prompts

TL;DR: grok CLI 1.0.46 moves prompt text past roughly 100k characters into a side file. The review runner disallows file tools, so Grok never read that text. Every Grok review whose prompt exceeded the limit was partly blind: across eight jurisdictions, no Grok quote came from the middle of its prompt. `--verbatim` sends the prompt whole, and the fix adds it.

## Marker test

Real ordinance text, cut to N characters, with nine markers spaced evenly through it. Grok was asked to list the marker values and write MISSING for any it could not see. The flags matched production (`--disable-web-search --disallowed-tools <review list> --no-subagents`).

| Prompt characters | Without `--verbatim` | With `--verbatim` | Input tokens (verbatim) |
|---|---|---|---|
| 120,000 | marker 7 missing | not run | |
| 180,000 | markers 5-7 missing | not run | |
| 240,000 | markers 4-7 missing | all 9 seen | 62,578 |
| 300,000 | markers 3-7 missing | not run | |
| 650,000 | markers 2-7 missing | all 9 seen | 168,896 |

Without the flag, Grok kept saying it would "read the omitted middle of the request" and then could not, because it had no file tool. The Palm Beach failure that started this, "model output does not contain a JSON object", was Grok answering in prose that the use matrix "was not included in the message I can read".
