# Z0.3 pipeline: fail-first evidence (v0.1.0)

**Date:** 2026-10-10 · **Covers:** `ozr.fetch`, `ozr.segment`, `ozr.models`, `ozr.labels` (extract and review), `ozr.grade`, `ozr.measure`, `ozr.mutation`, `ozr.release` and their 28 new tests. No real jurisdiction was fetched or extracted in this step, and no test calls the network or a model.

## Method

As in Z0.0 and Z0.1, the logic under test was replaced by stubs and the new tests were run against them. The stubs were applied to a `git archive` copy of commit 3271152 in a scratch directory, so the working tree was never modified. Each stub was appended to the end of its module, so it shadows the real function.

Run 1 stubs:
- `fetch.policy_errors` returns no errors; `fetch_state_rules` writes an empty source list; `fetch_geometry` does nothing; the fetch CLI accepts anything; `contamination.USER_AGENT` reverts to the Z0.0 string with no contact;
- `segment._located_pages` locates nothing and `render_pages` renders nothing;
- `models._environment` passes the parent environment through unchanged, `run_claude`, `run_codex` and `run_grok` return an empty result without running anything, and `parse_json_object` returns `{}`;
- `labels.label_errors` accepts every label;
- in `grade`, `apply_grade_rules` never caps or marks stale and `cell_errors` accepts everything;
- in `measure`, `_subset` returns no metrics and `_kappa` returns null;
- `mutation.mutate` changes nothing;
- `release.build` writes nothing and reports no errors.

Run 2 targeted the four tests that run 1 left passing:
- `fetch_jurisdiction` opens every source, analyst_fetch included, and always reports `new`;
- `segment.page_texts` keeps HTML tags;
- `mutation.mutate` flips every symbol on every line, prose included, and its output is not seeded.

## CLI output shapes

The parsers are tested against real outputs, not invented ones. Before any parser was written, each CLI ran one trivial prompt with nothing to do with zoning: `claude -p` (stream-json, with an image), `codex exec --json` (with an image) and `grok --output-format json`. The outputs were scrubbed of session and request ids and kept in `tests/fixtures/cli/`.

## Cross-model review fixes

A second model (grok) reviewed the stage code. Each confirmed finding was reproduced, then fixed. Each fix has a test, and those tests were run against commit 277163b, before the fixes:

| Finding | Reproduced by | Fix |
|---|---|---|
| A statute redirect could land on any host that is not on the denylist | `test_statute_redirect_off_the_approved_host_is_refused` | The final URL must stay on the host that triage approved |
| A paged geometry fetch skipped rows when the server capped pages below 1000, and looped forever when a page was empty | `test_geometry_paging_follows_short_pages_and_stops_on_an_empty_page` | The offset advances by the rows returned, and an empty page stops the loop |
| A moratorium on `"*"` use classes did not mark cells stale | `test_a_moratorium_on_all_classes_marks_cells_stale` | `"*"` matches every class |
| The release gate did not hash `other_files` (`denylist.txt`) | `test_a_wrong_other_files_hash_fails_the_release_gate` | `_hash_errors` covers `other_files` |
| codex as a reviewer could read the repository, including the other models' answers, through its shell tool | `test_codex_adapter_copies_images_and_parses_usage` (argv) | Shell, exec, code-mode, browser, app and image-view features are disabled and MCP servers are emptied. A live probe asked to read a file in the repo answered `NO-TOOLS`; a control run without the flags quoted the file |
| grok ignores `--tools ""` and read a repository file in a live probe | `test_grok_adapter_is_text_only` (argv) | Every built-in tool is removed by name with `--disallowed-tools`. The same probe then answered `NO-TOOLS` |

The extractor invocation (`claude -p` with `--tools ""`) was probed the same way. Its init event listed no tools and no MCP servers, and it answered `NO-TOOLS`.
