# Z0.1 taxonomy, schema, gates and contract port: fail-first evidence (v0.1.0)

**Date:** 2026-10-09 · **Covers:** `taxonomy/v1.json`, `schema/*.schema.json`, `ozr.gates`, `ozr.contract`, the fixture release under `tests/fixtures/`

## Method

As in Z0.0, the logic under test was replaced by stubs that accept everything, the suite was run, the real files were restored from copies taken beforehand, and the suite was re-run. Stubs:
- every gate in `ozr.gates` returns no errors: `quote_errors`, `section_errors`, `enum_errors`, `absence_hits`, `absence_errors`, `coverage_errors`, the URL check, and the release-level hash, grade, staleness, preemption, denylist and statute-quote checks; `canonical` returns its input unchanged; `apply_grade_rules` returns the cell unchanged;
- `ozr.contract.check_answer` and `check_release` return no errors;
- every file in `schema/` is replaced by an empty 2020-12 schema, which accepts any instance.

Run 2 stubbed what run 1 left real: `taxonomy/v1.json` emptied, and `add_months` returning its input. Run 3 used stubs that reject everything, for the tests whose expected result is no errors.

## Contract parity

`tests/fixtures/contract_parity/expected.json` was generated once by running the consumer contract's reference implementation (`checkAnswer` and `checkRelease`, JavaScript, Node 26.8.2) over `cases.json`. The cases are 36 answers and 25 manifests, and they reach every error string the two functions can emit. The cases include the places where Python and JavaScript differ:
- a missing key, which is not null;
- a trailing newline in a date or version;
- full-width digits;
- an upper-case `HTTPS://`;
- a host with a port;
- a trailing-dot host;
- `..` inside a file name;
- numeric fields;
- a nameless file.

`ozr.contract` matches the reference output exactly, in order, for every case. The golden file was regenerated from the reference after the port was written and compared byte for byte: it is unchanged.
