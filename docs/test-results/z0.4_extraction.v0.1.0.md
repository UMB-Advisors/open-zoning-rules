# Z0.4 extraction: run record and fail-first evidence (v0.1.0)

**Date:** 2026-10-10 · **Covers:** the Z0.4 extraction run over the 10 pilot jurisdictions, the six pipeline fixes it needed, and their six new tests.

## TL;DR

- Five jurisdictions have extractable ordinance text: Warrenton, Loudoun, Pittsylvania, Douglas and Lake. Lake's text is an unadopted draft. Extraction produced 665 cells that pass the gates and 245 that were rejected, a **gate rejection rate of 26.9%**.
- The other five (Hillsborough, Polk, Atlanta, Coweta, Fauquier) have no ordinance text in the cache, so they were skipped without a model call. They stay analyst_fetch, and the primary-source rule was not worked around.
- Claude cost, as `claude -p` reported it: **$22.03** for the runs kept, **$25.30** including the two first runs that the fixes replaced.
- The run found six pipeline bugs. Each fix has a test, and each test was shown failing against the unfixed code.

## Run

Fetch ran once as a single batch for all 10 jurisdictions (`python -m ozr fetch --all --online`, 2026-10-10 08:46:19Z to 08:47:32Z), not one jurisdiction at a time:
- 30 sources: 22 unchanged, 8 skipped as analyst_fetch, 0 failed.
- One changed: `us-51107-zo-faq`, an HTML FAQ page whose bytes differ from triage. The previous sha256 is in `runs/us-51107.jsonl`. Every other re-fetch reproduced its sha256.

The adapter uses `--input-format/--output-format stream-json` rather than `--output-format json`, because page images go in on stdin. ### Why cells were rejected

| Gate error | Count | Jurisdictions |
|---|---|---|
| Table row label not found in the source text | 124 | Loudoun 47, Douglas 60, Lake 17 |
| Section not printed as cited (for example "Sec. 35-402" where the code prints "§ 35-402") | 65 | Pittsylvania 30, Lake 35 |
| Table column header not found | 25 | Loudoun |
| A taxonomy term occurs in the code but the cell's absence hits do not explain it | 44 | Pittsylvania 21, Lake 17, Douglas 6 |
| Definition section not found | 5 | Lake |

One cell can carry several errors.

The row-label failures are the known risk from plan section 6, that use tables lose structure in PDF text extraction. pdfplumber wraps long row labels across lines (for example "Wholesale and P P P P P P" followed by "Warehouse" on the next line), so a correctly copied label is not a substring of the text. The gate is working as designed, and it was not loosened. Whether to recover table structure with pdfplumber's table extraction is a decision for after Z0.5.

## Pipeline fixes

| # | Bug found in the run | Fix | Test |
|---|---|---|---|
| 1 | The absence gate read only the source a cell cites. Warrenton's unlisted-use clause is in Article 2 and its district lists are in Article 3, so all 84 cells were rejected with "unlisted rule quote not found in source" | Quote and section checks stay on the cited source. The absence gate reads every cached source of the jurisdiction | `test_absence_gate_reads_every_source_of_the_jurisdiction` |
| 2 | List-style codes lost pages. "Permissible Uses" did not match, and a district list that runs onto the next page was dropped. The model reported the Warrenton commercial lists as truncated | `USE_TABLE_RE` also matches "permissible uses" and "uses permitted". A heading match also selects the next page | `test_list_style_use_pages_keep_their_continuation_page` (and `test_segments_pdf_html_and_missing_bytes` updated to the new rule) |
| 3 | 84 cells used 30,632 output tokens, about 365 per cell, so Loudoun's 399 cells cannot fit in one response | Labelling is chunked to 5 districts per call. The ledger keeps one record with summed tokens, cost and wall time and `calls`. A failed chunk records the calls already paid for | `test_labelling_is_chunked_by_district_and_usage_is_summed` |
| 4 | Douglas's Table 2.2 spans about 150 pages. 141 page images exceed the API's 100-image and request-size limits | At most 40 images per call, keeping pages that name a taxonomy term first | `test_image_cap_keeps_pages_naming_a_taxonomy_term` |
| 5 | The model was called for jurisdictions with no segments | Extraction is skipped and recorded in the ledger, with no model call | `test_extract_skips_a_jurisdiction_with_no_segments` |
| 6 | In Pittsylvania, 63 of 98 cells set `source_id` to the page marker, e.g. "us-51143-zo-ch35 page 85" | A known id followed by " page <n>" resolves to the id. Unknown ids are still rejected | `test_marker_page_suffix_in_source_id_is_stripped` |

## Caveats for Z0.5 and Z0.6

- **Lake:** its cells come from the unadopted 2026 schedule-of-uses draft, not the adopted LDR.
- **Loudoun:** Chapter 3 is the 2023 adopted clean copy. The 2025 data-center amendment (special exception in IP, GI and MR-HI) appears only on the county's project page. The extractor quoted the table for some districts and the project page for others, so the datacenter cells are inconsistent until review.
- **Nothing was tuned against `tests/known_answers.json`.** The prompt is unchanged (`extract.v1`).
