# Z0.8 gate fixes: evidence (v0.1.0)

**Date:** 2026-10-11 · **Branch:** `feat/z0.8-gate-fixes`, stacked on `feat/z0.7-release-v0.1.0` (6e32a30) · **Covers:** the 13 confirmed findings of the cross-model review of `origin/main...origin/feat/z0.7-release-v0.1.0`, and four maintainer decisions.

## TL;DR

- **The release gate now passes.** `python -m ozr release --version 0.1.0 --published 2026-10-11` exits 0 (before: exit 1, 137 errors). The consumer contract `zoning-atlas.release/0.1` reports 0 errors over 550 records, both in `ozr.contract` and in the consumer contract reference implementation run read-only.
- **Fewer cells are published: 550, down from 776, and 360 are withheld.** Every withheld cell is listed in `releases/v0.1.0/withheld.json` with the gate that failed and its run id. Most of the drop comes from the per-occurrence absence gate: published `unlisted` cells fell from 380 to 171, because the model outputs explain only some occurrences of each term. No model was called; the existing outputs were re-gated.
- **Known answers.** Before: 15 match, 5 miss, 1 unscored (counted with the corrected rule; the committed `accuracy.json` listed 7 misses). After: 15 match, 2 miss, 4 unscored. Douglas OI and C-H and Pittsylvania M-2 are now withheld, not corrected. **Loudoun MR-HI is still published wrong**, because no gate can catch it (see Deferred).
- **The known-answer score is no longer a blind check.** The gates were changed against those exact cells. From here on the 60-cell human audit is the only blind check.
- All 13 findings are fixed. Every new test was shown failing on the unfixed code (or, for one case, on a stub); the output is below.

### The consumer ignores an extra release file

Checked before adding `withheld.json`, by reading the consumer contract reference implementation of `zoning-atlas.release/0.1` (read only, not edited). Its `checkRelease(manifest)` reads only the manifest fields `schema`, `version`, `published`, `licence` and `schema_url`, and for each entry of `files[]` it checks `format` (`geoparquet` or `json`), a relative `path` and a 64-hex `sha256`. It never lists the release directory and never opens a file. `checkAnswer(record)` reads only the record. So an extra file is invisible unless the manifest lists it, and a listed JSON file with a hash passes. `withheld.json` is listed as `{"format": "json", ...}` so the repository's own hash gate covers it. Running that implementation on the rebuilt manifest gives `checkRelease` = `[]` and 0 `checkAnswer` errors over the 550 records.
