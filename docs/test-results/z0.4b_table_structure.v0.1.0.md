# Z0.4b table structure: run record and fail-first evidence (v0.1.0)

**Date:** 2026-10-11 · **Covers:** rebuilding use-table rows from PDF rulings, the gate change that accepts a match in either the raw text or the table text and records which one, the re-run of extraction on the five extracted jurisdictions, and five new tests.

## TL;DR

- Segmentation now rebuilds each PDF table from its thin rulings. A wrapped row label becomes one string ("Floating Solar Facility | P | P …"). That table text is appended to the source's full text after a fixed marker.
- The gates still require an exact canonical substring. A string now passes if it is in the raw layer **or** in the table layer, never across the boundary between them. Each passing cell records which layer matched each field. **No gate was loosened.**
- Fresh extraction gives **865 passed and 45 rejected, a gate rejection rate of 4.9%** (Z0.4: 665 and 245, 26.9%). Cost is **$27.78** (Z0.4: $22.03).
- Permitted cells go from 5 passed / 36 rejected to **40 / 0**. Conditional cells go from 40 / 23 to **58 / 5**. **Permitted is still below Z0.6's minimum of 50 per status.** No gate rejects permitted cells any more, so the remaining shortfall is in the data itself: these five codes contain few permitted cells.
- A no-cost control re-gated the Z0.4 model output against the new text and reproduced Z0.4 exactly against the old text. On the new text, every row-label and column-header rejection cleared, and no new absence-gate hits appeared.

## How table text is built

`segment.pdf_pages` makes one pdfplumber pass per PDF. For each page it:
- keeps `extract_text()` as the raw text, unchanged byte for byte;
- treats as rulings `page.lines` plus every rect no more than 2pt thick, and runs `extract_tables` with the explicit strategy on those rulings.

Thick filled rects are ignored, for two reasons:
- Loudoun shades each text line of a cell with its own 11pt band. The default `lines` strategy uses every rect edge, so it split "Wholesale Distribution, Warehousing and" and "Storage" into separate rows.
- With rulings only, Loudoun, Lake and Douglas all come back with whole cells. Loudoun's headers are whole too: "TRC Inner Core" and "SCN-16".

Wrapped fragments within a cell are joined with a space, but with no space around a hyphen, so "SCN-\n16" becomes "SCN-16" and "CC\n-\nNC" becomes "CC-NC". `canonical()` already closes a hyphen between letters, but not a hyphen before a digit.

A page with fewer than two rules in either direction has no table text. Pages are closed as they are read.

Every page of each PDF is processed, not only the located pages, so the table text depends on the source bytes alone. The raw layer of every one of the 12 cached text files was checked to be identical to its Z0.4 text.

HTML sources (Loudoun's FAQ and project page, the county pages) get no table text. They are out of scope for this step.

## How the gate uses it

- `gates.TABLE_TEXT_MARKER` separates the two layers in `cache/text/<source>.txt`. The extract gate and the release gate read the same file, so their results agree.
- `match_layer` returns `raw`, `table` or nothing. It replaces `contains(text, …)` in the following checks:
  - the row-label and column-header "found in source" checks;
  - the prose and absence quote check;
  - the definition quote check;
  - the section check;
  - the absence-hit and unlisted-rule quote checks.
- These checks are unchanged:
  - "label in quote", which compares against the cell's own quote;
  - term detection for the absence gate, which still reads the whole text.
- Each passing cell carries `matched_text`, e.g. `{"row_label": "table", "column_header": "raw", "section": "raw"}`. The extraction output carries `matched_text_counts`. The field sits at the cell's top level, because `evidence` does not allow extra keys in `schema/record.schema.json`.

## Fail-first evidence

As in Z0.4, the tests ran against copies in a scratch directory, never against the working tree.

**Run 1: the old gate on the new fixture.** The fixture table PDF went through the Z0.4 head (8edcd15) `page_texts` and `quote_errors`:

```
'Table of Permitted Uses SCN- CC\n16 -\nNC\nFloating Solar P P\nFacility\nWholesale Distribution, S\nWarehousing and\nStorage'
['us-00000/X/u: row label not found in source', 'us-00000/X/u: column header not found in source']
['us-00000/X/u: row label not found in source', 'us-00000/X/u: column header not found in source']
```

The new test files collect with an ImportError against 8edcd15, because they need the new names. Runs 2 to 5 therefore stub each piece of logic out of the fixed code, so that each failure is a failure of behaviour.

## Caveats for Z0.5 and Z0.6

- **Permitted is at 40, below 50.** The listed-status gate in Z0.6 would still report insufficient data for permitted. Nothing in the gates now rejects permitted cells; these five codes simply have few by-right cells for the taxonomy's classes.
- **Fresh run vs control.** The fresh run's improvement beyond the control comes partly from model variance: section formats, absence explanations and the number of unlisted cells. The control is the clean measure of the table-structure fix.
- Lake's cells still come from the unadopted draft. Loudoun's data-center caveat from Z0.4 still applies.
- Nothing was tuned against `tests/known_answers.json`, and the prompt is unchanged.
