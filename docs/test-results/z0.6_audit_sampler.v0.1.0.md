# Z0.6 audit sampler: fail-first evidence (v0.1.0)

**Date:** 2026-10-11 · **Covers:** `pipeline/ozr/audit.py` (`python -m ozr audit`), the five tests in `tests/test_audit.py`, and the frozen sheet `audit/z0_audit_sheet.v0.1.0.csv`.

## TL;DR

- The sampler draws published cells stratified by status, then jurisdiction, with a fixed seed. It writes only the cell key, jurisdiction, district, use class, source URL and section, plus empty columns for the human. No model answer is written.
- Each test was shown failing: all four original tests against a stub sampler, the blindness test against a sampler that leaks the status, and a fifth test against the first implementation, which had a real bug.
- The first draw from the buggy sampler gave **18 rows instead of 60**. The fifth test reproduces that bug. After the fix the sheet has 60 rows, 15 per status.

## What the sampler does

- It reads each jurisdiction's `cells.json` (published cells only).
- The quota is `n // 4` per status (`permitted`, `conditional`, `prohibited`, `unlisted`). A status with too few cells gives what it has, and the shortfall is shared among the statuses that still have cells.
- Within a status, each jurisdiction's cells are sorted by key and shuffled with `random.Random(f"{seed}:{status}:{jid}")`. Cells are then taken round-robin across jurisdictions.
- Rows are sorted by cell key, so row order does not reveal the strata.

**2. Against a sampler that writes the model's status into `human_status`:**

```text
FAILED tests/test_audit.py::test_rows_and_csv_are_blind_and_have_only_header
1 failed, 3 passed in 0.07s
```

**3. Against the first implementation.** Its round-robin loop used `for ... else: break`, so it left a status after one pass over the jurisdictions. That capped each status at one cell per jurisdiction. The four original tests passed, because every fixture quota was no larger than the number of jurisdictions. On the real data it drew 18 rows. The new test `test_quota_larger_than_jurisdiction_count_is_filled` asks for 40 cells from 3 jurisdictions:

```text
E       AssertionError: assert 12 == 40
FAILED tests/test_audit.py::test_quota_larger_than_jurisdiction_count_is_filled
1 failed, 4 passed in 0.11s
```

The fix keeps cycling until the quota is met. That always ends, because each quota is capped at the cells available. After the fix: `5 passed`.
